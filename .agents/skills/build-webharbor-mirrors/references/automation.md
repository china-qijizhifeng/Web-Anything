# One-URL automation contract

Use this reference when the user wants a site URL converted directly into a local
WebHarbor candidate.

## Command

```bash
.agents/skills/build-webharbor-mirrors/scripts/run.sh build https://example.gov/
```

This is the supported unattended entry point. It creates or reuses the ignored
`.assets/builder-python` dependency directory, installs the versions pinned in
`requirements-builder.txt`, installs Chromium under `.assets/playwright`, enables
hash-checked resume, and runs the complete candidate pipeline. The only required
site input is a public URL or domain. Use `WEBHARBOR_BUILDER_DEPENDENCY_PATH` or
`PLAYWRIGHT_BROWSERS_PATH` only to relocate those machine dependencies.

To run the same URL-driven workflow through the Codex SDK and retain every
SDK-visible reasoning summary, assistant message, command/result, file change, MCP
call, plan, error, and usage event, use:

```bash
.agents/skills/build-webharbor-mirrors/scripts/run.sh trace-url https://example.gov/
```

The trace runner uses the Responses configuration supplied through the process
environment, constructs the
mirror in an isolated workspace, records SDK-visible events, recursively redacts
credentials from the top-level trace, and asks a second turn to edit only an
independent skill proposal. It never applies that proposal to this production
skill. Hidden chain-of-thought that Codex does not expose as an SDK event is not
available and must not be reconstructed.

Prefer `--skip-artifact` while iterating mirror quality:

```bash
.agents/skills/build-webharbor-mirrors/scripts/run.sh trace-url \
  https://example.gov/ --site example_trace --skip-artifact
```

The outer `mirror-artifact.tar.gz` is a share/merge convenience, not a mirror
acceptance gate. With `--skip-artifact`, judge completion from
`workspace/sites/<site>/`, `workspace/mirror_factory/evidence/<site>/`, and the
site package/evidence generated by the WebHarbor pipeline. Generate or seal an
outer archive only when an exportable merge package is needed. See
`docs/codex-mirror-trace.zh-CN.md` for the trace and artifact contract.

When continuing a trace after a model timeout, do not treat the absence of
`final.md`, `reflection.md`, or a sealed outer archive as a mirror failure by
itself. Inspect the workspace evidence files directly. If the recoverable issue is
semantic, such as "classified links are not actually usable", write a focused
continuation brief and run with `--skip-artifact`.

When a homepage itself is unavailable but a representative, public,
robots-allowed content route on the exact same origin succeeds, the replacement
queue may record that route as `capture_url` while retaining the frozen canonical
site as `upstream_url`. The pipeline passes the latter as `--represented-url`,
requires same-origin URLs, records both in automation/intake/spec evidence, and
maps the captured entry to the local root. This is not permitted for a sibling,
archive, cache, proxy, or access-control workaround.
The local `/` must render the declared representative content itself. Do not leave
the canonical homepage broken, exclude it from verification, or redirect users to
a passing subpage.

`build-from-upstream` remains the low-level entry for controlled environments. Set
`WEBHARBOR_SKILL_PYTHON`, `WEBHARBOR_RUNTIME_PYTHON`, and optionally
`WEBHARBOR_RUNTIME_DEPENDENCY_PATH` when using it directly.

For preview checks launched from an isolated trace workspace, pass the production
builder/runtime dependency and Playwright browser paths explicitly when available;
otherwise the workspace may try to reinstall Flask/Playwright from the network. If
Chromium fails with a Linux sandbox error such as `sandbox_host_linux.cc` /
`Operation not permitted`, rerun the same browser audit in the approved
non-sandbox execution environment. Do not report that as a site-rendering failure
unless the browser can launch and the page itself fails.

## Stage order

1. `environment`: verify runtime Flask imports and fidelity browser-library imports
   before spending the upstream request budget.
2. `intake`: normalize the URL and infer a collision-safe ID; fetch robots first;
   reject private-network targets, cross-site redirects, access controls,
   challenges, ambiguous rights basis, and non-HTML entries; derive non-sensitive
   stateless GET searches and one-option select/checkbox/radio filters from captured form fields,
   visible terms, visible option labels, and safe defaults. Directly declared
   presentation CDNs for styles, fonts, images, and video posters may add up to six
   asset-only hosts; each receives its own robots and public-address checks, while
   third-party script and analytics hosts remain excluded.
   The HTML response budget is 5 MB per page so modern public SPA shells remain
   eligible without making the capture unbounded.
   Robots rules use path-plus-query matching with RFC 9309 wildcard, end-anchor,
   longest-rule, and allow-on-tie semantics; literal `?` rules are never collapsed
   into a root disallow.
3. `manifest`: register a greenfield target with the generated capture contract.
4. `capture`: issue delayed public GET requests inside exact page and asset scope;
   preserve response bytes, final URLs, hashes, redirects, and failures. A generated
   query host gets an independent robots check; its rejection is recorded as an
   optional query failure and never replaced with synthetic content. Scan the first
   captured pages once more for search/filter forms not present on the entry page
   and add exact URLs up to a global two-variant budget. Record unavailable referenced
   assets as fidelity gaps; entry-page, robots, scope, and challenge failures remain
   hard stops, while the later matched screenshots decide whether a missing asset is
   materially harmful. Capture directly referenced same-scope scripts and module
   preloads as hashed assets. For a page that remains a JavaScript-only shell,
   execute only the captured resource map in an isolated desktop browser, block
   every uncaptured request, WebSocket, service worker, and non-GET request, then
   serialize a meaningful DOM with its source/resource/DOM hashes and blocked-request
   evidence. Record and skip denied secondary navigation samples rather than
   discarding an otherwise valid bounded capture.
   Schedule resources globally across captured pages and dynamically discovered CSS
   dependencies: CSS first; script/fetch/XHR second; fonts third; direct image/media
   fourth; lazy/srcset image/media last. Count only successful
   assets against the asset capacity while enforcing a separate hard attempt
   bound. Reserve one bounded capacity slot for each promoted prerender resource,
   never shrink an automatically expanded budget on resume, and preserve every
   hash-verified reused asset before adding new dependencies.
   Audit every captured page in a JavaScript-disabled 1440x900 browser with bounded
   lazy scrolling, promote only exact GET resource URLs, infer CSS/JS/font/image
   types when Chromium reports `other`, and fetch each external presentation CDN
   only after its own robots/public-address check. Resolve CSS dependencies
   immediately and stop after at most six no-more-than-2048-resource convergence
   rounds. A robots denial, WAF, 404, or remaining resource never becomes a
   placeholder success.
   Scan verified page attributes and hash-verified captured page-host scripts for
   bounded same-site `.lottie`/`.wasm` runtime resources. Promote only URLs already
   inside declared asset scope, reserve one capacity slot per promoted resource,
   and rerun the normal robots-aware GET capture. Ignore dynamic expressions and
   external library fallbacks.
5. `reconstruction`: verify all capture hashes; rewrite the captured DOM, routes,
   forms, CSS, and resources to local equivalents; generate a compressed seed
   bundle, candidate tasks, `workflow_gaps.json`, and `mirror_contract.json`.
   The contract inventories every route, SQLite record, asset source, and declared
   workflow. Compile pages only from the entry URL's exact origin plus explicit
   generated query URLs; captured sibling `docs.` or `help.` pages remain external.
   Screenshots are reference-only and never become served assets.
6. `seed`: import the app twice in two clean directories and require identical
   canonical SQLite bytes plus a byte-stable populated re-import.
7. `catalog`: preserve existing port order, register `candidate_reconstructed`,
   pin the generated seed hash, and extend Docker's final exposed port if needed.
8. `audit`: verify required paths, task definitions, Python syntax, isolation,
   runtime-data rules, SQLite integrity, and tree hash.
9. `runtime_local`: start through the real control plane, dirty SQLite, reset it,
   and require the runtime database to match the seed byte-for-byte.
10. `fidelity`: run the generated site, replay the SHA256-verified captured
    HTML/CSS/image bytes or traced captured-resource DOM in an isolated browser
    with every uncaptured request blocked, and apply the compiler's auditable
    collapsed-control and static-widget states to both sides. For replay, compare
    both sides with JavaScript disabled, then sample the local site again with
    JavaScript enabled. Compare up to three 1440x900 routes and reject blank or
    structurally empty pages, visible broken images, missing stylesheets,
    missing-asset placeholders, uncaptured/failed/HTTP-error critical resources,
    CSP errors, external local requests, nonblank retention below 0.5, or visual
    similarity below the declared threshold. One incomplete capture replayed on
    both sides can still score 1.0, so pixel similarity never overrides these
    independent gates.

    Page stabilization waits briefly for network idle and fonts, scrolls at most
    12 steps/eight viewport heights for nearby lazy assets, and retries a destroyed
    main execution context no more than three times. Do not use a live growing
    `scrollHeight` as a loop bound. Blocked third-party iframes can enter
    `chrome-error://`; preserve their missed request type while keeping the
    top-level capture bounded. A pinned historical screenshot records upstream
    resource inspection as not applicable to the static reference, but the local
    matched and JavaScript runtime samples still cross all integrity gates.

    Local `/` is mandatory in the pinned fidelity spec and emitted route results.
    It cannot appear in `excluded_routes`. A source-blocked homepage therefore
    keeps fidelity failed unless a representative exact-origin source was declared
    before reconstruction and is mapped honestly to local `/`.

    Current passing evidence must use `webharbor-fidelity-v19`, contract version
    3, unchanged spec/source hashes, complete-resource enforcement, runtime
    JavaScript verification, and a nonblank threshold of at least 0.5. This
    prevents current-site drift, stale proof reuse, and a second live upstream
    fetch after the robots-aware capture already passed.
11. `quality`: require current visual evidence, verify every contract data record
    against the seed SQLite database, run every declared GET/POST workflow with a
    cookie-preserving session, and run declarative `browser_navigate`,
    `browser_fill`, `browser_select`, `browser_set_input_files`, `browser_click`,
    and `browser_expect` steps against real desktop controls. Upload fixtures must
    be hash-pinned synthetic files under `sites/<site>/quality_fixtures/` and may
    not exceed 1 MiB. Browser traffic is restricted to the exact
    local origin. Mark browser actions that mutate state with `state_change: true`
    and prove them with a later SQLite assertion. Restore the runtime database from
    seed, compare exact responses, and reject screenshot crops, undisclosed data,
    or interaction gaps. Write `quality.json` with `full_fidelity`,
    `synthetic_grounded_data`, or `rejected`.
12. `package`: write a deterministic local `.assets/generated/<site>.tar.gz`
    containing the seed and managed capture/replay assets. Publication is recorded
    as pending because uploading to the shared dataset requires separate external
    credentials and authority.

Every stage writes status to `mirror_factory/evidence/<site>/automation.json`, and
every terminal outcome writes the compact `result.json`. Exit `0` is passed/stopped,
`2` is a policy rejection, `3` is an environment prerequisite, and `4` is another
pipeline failure. Resume reuses only passing intake/capture artifacts whose upstream
origin, spec hash, and local bytes still match. A rejection or failure is a valid
automated result; do not weaken the guardrail to make the command pass.

## Deployment handoff gate

Before providing a user any deployment URL, start the local site and run:

```bash
run.sh audit-candidate-resources \
  --site SITE=http://127.0.0.1:PORT/ \
  --require-current-quality
```

This is a real Chromium render check, not an HTTP probe. It requires a meaningful
non-redirected `/`, loaded stylesheets, no missing-asset placeholder, no broken or
external resources, and current passing fidelity plus three-fidelity quality
evidence. `quality.json` with `grade=rejected` is an inspection-only candidate.
Never describe it as complete, usable, or high-fidelity. A healthy process, HTTP
200, or good screenshots from selected subpages do not override this gate.

For a user-explicit, local-only benchmark snapshot, `--private-research-snapshot`
records that bounded basis in intake/spec/queue evidence. It does not assert an open
license, permit publication, broaden host/path scope, bypass a robots denial or WAF,
or allow authentication and personal data. RFC 9309 `404`/`410` robots responses
are recorded as unavailable and allow crawling; explicit disallow and access-control
responses remain hard stops.

## Reconstruction semantics

The generated `app.py` is intentionally a common replay runtime. It does not
generate a common UI. Each site's actual HTML, text, styles, images, routes, and
query strings are compiled from its own verified capture and seeded into SQLite.
Captured internal links remain local. Captured assets are served by hash-derived
keys. CSS URLs are rewritten against the captured asset map. External navigation,
missing assets, uncaptured routes, POST submissions, and uncaptured query variants
produce local bounded behavior and are counted in `workflow_gaps.json`.
Observed same-site redirects become SQLite aliases so both the linked and canonical
routes work locally. Exact captured search and select/checkbox/radio filter variants are replayed;
unknown query variants return a scope notice rather than unrelated path-level
fallback content.
Inline executable code is removed by default. The compiler preserves only bounded,
static local-DOM initialization statements from a strict allowlist and pins each
exact retained body with a CSP SHA-256 source. It does not enable `unsafe-inline`.
Captured scripts may execute only when their bytes are hash-verified, their source
host is a declared page host, and their URL is rewritten to a local asset. Unknown
scripts, narrowly recognized telemetry, inline event handlers, workers, and external
runtime requests remain removed or blocked. A claimed collapsed control must have a
passing local browser workflow that asserts the closed state, clicks the real
control, and asserts target visibility plus `aria-expanded=true`.
Exact quoted same-site asset literals inside those scripts may be rewritten only
when the referenced bytes were separately captured and hash-verified. A captured
WASM asset receives the narrow `wasm-unsafe-eval` CSP source; this does not permit
JavaScript `eval`, uncaptured network fallback, or dynamic API discovery.
For Splide widgets whose library CSS hides all pre-initialized content, the compiler
adds the library's own rendered-state class so the authentic first frame remains
visible without executing the removed initializer. This static fallback is counted
as a workflow gap; it does not claim carousel controls are interactive.
Preserve JSON/JSON-LD data scripts, remove inline `on*` handlers, neutralize
`javascript:` URLs, and
discard pure network-hint links. Remove the source of an uncaptured iframe only
when DOM/CSS proves it is hidden or 0x0, and record that normalization. Do not
remove or ignore missing stylesheets, visible images, video, fonts, or other
presentation resources to make fidelity pass.
Recognize image-load handlers only by exact safe bodies such as setting the image
opacity or its parent `data-loaded` flag. Replace those handlers with the successful
static state, mark the image for audit, and apply the identical normalization to the
captured fidelity baseline. Do not generalize this to arbitrary event-handler code.
Resource sweeps must trigger browser-native lazy image loading and wait for decode
completion before reporting `complete=false`; a below-fold lazy image is not a
broken image until loading has actually been attempted.
Classify exact Google Tag Manager and Netlify RUM setup as noninteractive telemetry.
Classify Cloudflare Turnstile separately as an external form guard, and remove it
only when the captured form action has a deterministic local SQLite backend. For an
Astro action, preserve the captured success response media type/body so the original
client renders its real success state. Prove the submission with browser fill/click,
visible success DOM, and a SQLite assertion.
Store site-specific interactive proofs in `interaction_workflows.json`, pin source
page hashes, and require every Playwright selector to resolve uniquely at the
declared desktop viewport. Responsive duplicate DOM requires a visible-state or
container discriminator; never weaken strict locator semantics.
Localize both `href` and `xlink:href` on external SVG `<use>` elements while
retaining the symbol fragment; otherwise the browser silently requests a dead
root-relative sprite even when the sprite bytes were captured.
For strict Next.js streamed server chunks named `S:<number>`, the compiler and
captured baseline expose the already-captured server DOM without executing the
inline chunk-relocation runtime. The exact fallback is recorded as a static stream
chunk workflow gap.

Use declarative component extraction and a site-specific reconstruction when the
benchmark requires arbitrary search/filter combinations, JavaScript-only controls,
accounts, saved state, or other workflows that a read-only replay cannot reproduce
faithfully. Continue that refinement from the same capture evidence rather than
invented records.

## Focused commands

Use these only when diagnosing or replaying a stage:

```bash
run.sh intake-upstream https://example.gov/
run.sh capture-upstream mirror_factory/upstream_specs/example.json
run.sh compile-snapshot --site example
run.sh build https://example.gov/
run.sh build-from-upstream --resume https://example.gov/
```

`--stop-after` exists for tests and controlled inspection. A stopped pipeline is
not complete evidence.

## Catalog replacement queue

Use `run.sh replace-generated` to replace the catalog's frozen
`candidate_generated` backlog. The queue is sequential because each successful
site updates shared catalog and manifest files. It is resumable and writes a
machine-readable entry for every attempt. Before invoking the one-URL pipeline it
backs up the existing site's generated presentation, seed, catalog, manifest, and
Dockerfile. A failed or rejected attempt restores those bytes while preserving the
new intake/capture evidence. A site is marked passed only when reconstruction,
seed, audit, local reset, desktop fidelity, and packaging all pass.
When a compiler or pipeline correction changes a previously passed output, rebuild
only explicitly named entries with `replace-generated <site> --rebuild-passed`.
When only the fidelity contract changes, do not recapture first. Run
`run.sh reaudit-fidelity --jobs 4 --timeout 180`, then
`run.sh replace-generated --status`; the latter invalidates old evidence and
classifies current failures separately from stale proof.

For user-authorized local-only historical reconstruction, run
`discover-historical` against the frozen queue first. Its generated batch spec is
only an input proposal: selection is HTML-first (structure, semantic nodes, text,
controls, and bounding geometry), screenshot metadata is only a desktop-size gate,
and no queue entry advances until `replace-generated --historical-specs` completes
the normal transaction. Historical source evidence remains separate from live
intake/capture evidence and carries `publication: not_authorized`.

## Historical providers

Historical specs pin the batch-level provider and source revision, then pin every
selected row or file by identity and SHA256. Supported providers are:

| Provider | Primary design evidence | Required per-entry pins |
| --- | --- | --- |
| `mind2web` | Sanitized HTML plus benchmark element geometry | `website`, `split`, `row_index` |
| `weblinx` | HTML page plus bbox JSON from one public pre-interaction browser state | `demonstration`, page/bbox/screenshot paths and each file SHA256 |
| `webui_dom_snapshot` | Chrome DOMSnapshot tree, element layout bounds, line-level `textBoxes`, bounded computed styles, and inline SVG | `capture_url`, `row_index`, canonical DOM SHA256, stable row-metadata SHA256, screenshot SHA256 |

`weblinx` pins `McGill-NLP/WebLINX-full` at a full dataset revision. Its selected
browser event must be the first public state before an interaction; replay metadata
must tie the page, bbox, screenshot, URL, viewport, and zoom together. The retained
HTML is sanitized and bbox values are scaled into screenshot pixels. The replay
archive and unrelated demonstration events are not retained.

When live and label-based discovery fail, use the exact-origin fallback sequence
documented in `historical-fallbacks.md`: hosted index probe, exhaustive pinned
Parquet URL-column scan, fixed Common Crawl probe, then `finalize-abandonments`.
These stages are discovery/evidence only and never advance queue status. A new row
must still pass the normal HTML-first capture, transactional replacement,
runtime/reset, and desktop fidelity gates.

`webui_dom_snapshot` pins `gbenson/webui-dom-snapshots` at a full revision. The
canonical JSON hash of `dom_snapshot` is authoritative. Stable metadata excludes
the expiring dataset screenshot URL and pins requested/displayed URL, frame count,
capture options, dimensions, source identity, and source-image SSIM. The converter
requires one same-origin top-level document, validates layout and text-box arrays,
slices text using Chrome's UTF-16 offsets, retains only bounded safe computed
visibility/overflow values, and converts the DOM to sanitized HTML+bbox evidence.
The raw DOMSnapshot and temporary signed URL are not stored.

For all providers, the ordering of design evidence is mandatory:

1. HTML/DOM structure, class/ID vocabulary, semantic roles, text, controls, links,
   inline design attributes, and exact bounding geometry.
2. Captured CSS or bounded computed-style values when hash-tied to the same state.
3. The matched screenshot only for visual comparison and bounded palette
   calibration. Never copy screenshot pixels into a served page asset.

Do not infer containers, cards, columns, typography, controls, or page copy from
screenshot pixels. Do not add screenshot-derived backgrounds to generic empty
wrappers. A large screenshot-calibrated color surface is permitted only when a
large HTML `main`/`article` or explicit page/content/container element supplies its
geometry. Inline SVG geometry and colors remain code. Canvas and every other
visual require original bytes or a disclosed high-resolution replacement; neither
bounded nor full-page screenshot crops are served.

Example WebUI DOM batch spec:

```json
{
  "schema_version": 1,
  "provider": "webui_dom_snapshot",
  "dataset": "gbenson/webui-dom-snapshots",
  "revision": "40-char-dataset-revision",
  "config": "default",
  "split": "train",
  "license": "CC0-1.0",
  "minimum_source_image_ssim": 0.7,
  "entries": [{
    "site": "site_id",
    "upstream_url": "https://example.test/",
    "capture_url": "https://example.test/public/page",
    "row_index": 42,
    "dom_sha256": "64-char-sha256",
    "row_metadata_sha256": "64-char-sha256",
    "screenshot_sha256": "64-char-sha256",
    "minimum_pixel_similarity": 0.85
  }]
}
```

The canonical `upstream_url` remains the represented site. `capture_url` may be a
representative public route only on the exact same origin; it is mapped to local
root and never permits a sibling, proxy, archive, or access-control workaround.
